# Almaz Tour: восстановленный контекст

Дата: 18 октября 2026. Начальные разделы фиксируют состояние при восстановлении контекста. После анализа владелец разрешил реализацию; актуальные результаты приведены в разделе «Реализация после восстановления». Готовность внешних интеграций к публикации отдельно не подтверждена.

## Назначение и стек

Сайт туристического агентства Almaz Tour в Астане: поиск туров через Tourvisor и обращение к менеджеру через формы, телефон и WhatsApp. Не реализованы собственная система бронирования, оплата, личный кабинет, CMS или база данных.

- Next.js 16.2.10, App Router, React 19.2.4, TypeScript, Tailwind CSS 4.
- Motion — Dock-навигация, GSAP — отзывы; есть собственные эффекты Reveal и ClickSpark.
- Контент и отзывы хранятся в исходниках, фотографии — в public/images.
- Локально доступны Node.js 24.22.0, npm 11.19.1 и node_modules. Переустановка зависимостей для выполненных проверок не потребовалась.

## Интеграции

### Tourvisor

TourvisorModule вставляет внешний https://tourvisor.ru/module/init.js. Три публичных ID задаются через NEXT_PUBLIC_TV_SEARCH_ID, NEXT_PUBLIC_TV_HOT_HOME_ID, NEXT_PUBLIC_TV_HOT_PAGE_ID. В .env.example сохранены 9955693, 9955326, 9955327.

Есть скелетон и запасная кнопка WhatsApp. В текущей реализации таймер ошибки запускается после завершения загрузки скрипта: при зависшем запросе скелетон может остаться надолго. Появление любого дочернего элемента считается готовностью виджета, что не доказывает работоспособность поиска. Запасной текст пока только русский. Реальную работу поставщика и его кабинет в этом анализе не проверяли.

### Telegram и формы

Три API отправляют сообщения одному или нескольким получателям через TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, TELEGRAM_CHAT_IDS. Дубликаты получателей исключаются, отправки параллельны, таймаут 10 секунд. Доставка хотя бы одному получателю считается успехом; автоматических повторов нет.

Текущие API возвращают 400 на некорректное тело/JSON, 422 на неверные поля, 503 без настройки Telegram, 502 при полном отказе доставки и 200 при успешной/частичной доставке. Тела заявок не логируются. Надёжного хранилища заявок нет. Подписка отправляет уведомление менеджеру, не создаёт автоматическую рассылку. Отзыв отправляется менеджеру, не публикуется на сайте автоматически.

Формы имеют ru/kk-тексты, клиентскую и серверную валидацию. Заявка поддерживает короткий и подробный режим, возраст детей, несколько категорий отеля и контекст страницы. Черновики полей сохраняются в sessionStorage на 30 минут и удаляются после подтверждённой отправки. При анализе использованы только имитации доставки из тестов.

### SEO и адрес сайта

Есть metadata, Open Graph, schema.org TravelAgency, robots и двуязычный sitemap. Базовый URL берётся из NEXT_PUBLIC_SITE_URL, иначе используется https://almaz-tourkz.vercel.app. Перед публикацией следует сверить его с фактическим доменом. Публичная версия визуально не проверялась.

В спецификации от 16 октября и плане сохранены требования:

- Сохранить скольжение белой активной плашки навигации: 420ms cubic-bezier(0.23, 1, 0.32, 1).

- Не добавлять фиктивные цены, сотрудников и неподтверждённые обещания.

Это восстановленные решения из файлов предыдущей работы; текущий запрос — анализ. Старый план не запускался автоматически. Его чекбоксы не отражают фактический частичный прогресс, а статус спецификации «реализация ещё не начата» уже устарел.

## Подтверждённые проблемы

1. Сборку блокирует отсутствующий src/components/SmoothScroll.tsx, импортированный новым layout. Lenis также отсутствует в package.json.
2. tsc обнаруживает четыре ошибки: отсутствующий SmoothScroll, два вызова DestinationCard с неподдерживаемым locale и неявный any в ref компонента Reveal.
3. src/app/layout.tsx и вложенный src/app/[locale]/layout.tsx оба создают html/body, Header/Footer/main. Локализованный layout сейчас вложен в старую оболочку. Нужно завершить перенос корневого layout по руководству установленного Next.js, иначе появятся дубли и проблемы гидратации/языка.
4. Новый Header/Footer и страницы используют site-header, header-inner, theme-control, language-switch, surface, ink и другие классы, для которых в globals.css ещё нет необходимых правил. Нет CSS-системы тёмной темы. Наличие переключателя темы пока не означает готовый внешний вид.
5. Reveal больше не добавляет is-visible, но старый CSS всё ещё задаёт .reveal opacity:0. Эффект Web Animations не сохраняет конечное состояние. Секции могут оставаться невидимыми после анимации и без JavaScript.
6. DestinationCard и AccordionGallery сохраняют адреса без языка; переход из казахской галереи будет направлен редиректом на русский. Их собственные подписи также пока русские.
7. Тест каталога ошибочно требует различия всех заголовков причин между языками и падает на собственном имени «Дубай». Это само по себе не доказывает ошибку перевода.
8. ESLint не настроен под CommonJS тесты: 21 ошибка no-require-imports; дополнительно два предупреждения.
9. README частично устарел: описывает запись заявок в лог и работу без Telegram, хотя новые API возвращают 503 и не логируют тела. Указан Manrope, но CSS использует системный стек Segoe UI/Helvetica Neue/Arial.
